# Backend — Lendyabel Gallery

RESTful API built with Node.js and Express, managing photo uploads to AWS S3.

## ⚙️ Installation

1. Enter the backend folder:
    ```
    cd backend
    ```
2. Install dependencies:
    ```
    npm install
    ```
3. Copy `.env.example` to `.env` and enter your AWS credentials:
    ```
    cp .env.example .env
    ```
    Fill in:
    ```
    API_AWS_ACCESS_KEY=your_key
    API_AWS_SECRET_ACCESS_KEY=your_secret_key
    ```
4. Start the server in development mode:
    ```
    npm run dev
    ```
    The server runs at `http://localhost:3001`.

## 🔑 Key Endpoints

| Method | Endpoint                       | Function                      |
|--------|-------------------------------|-------------------------------|
| GET    | `/api/photos/allPhotos`       | List all images               |
| POST   | `/api/photos/upload`          | Upload new image (`file`)     |
| GET    | `/api/photos/download/:filename` | Download image by name     |
| DELETE | `/api/photos/:filename`       | Delete image by name          |

- Use the field `file` for uploads (multipart/form-data).

## 🗂️ Main Files

- `index.js`             — Entry point, loads env vars and starts the server
- `app.js`                — Express app configuration, static file serving and route mounting
- `modules/photos/routers/photoRouter.js` — Photo routes (list, upload, download, delete)
- `modules/photos/controllers/photoController.js` — Request/response handling for photos
- `modules/photos/services/photoServices.js` — AWS S3 SDK calls (list/upload/download/delete objects)
- `middleware/awsErrorHandler.js` — Custom AWS/Express error handling
- `public/` — Built frontend static files, served by Express and generated by the `frontend-deploy` script (not committed)

## 📦 Serving the Frontend

The backend serves the frontend as static files and falls back to `public/index.html` for any unmatched route (SPA routing). To build the frontend and copy it into `public/`:

```
npm run frontend-deploy
```

## 🚀 Deployment (Fly.io)

The app is deployed to [Fly.io](https://fly.io) as a single Docker image (Express serving both the API and the built frontend).

1. Build and deploy:
    ```
    fly deploy
    ```
2. Set the required secrets (only these two are used by the app — do not confuse them with any AWS/Tigris storage secrets Fly may auto-provision):
    ```
    fly secrets set API_AWS_ACCESS_KEY=your_key API_AWS_SECRET_ACCESS_KEY=your_secret_key
    ```
3. Check current secrets/config with `fly secrets list` and `fly status`.

Configuration lives in `Dockerfile` and `fly.toml`.

Check `DEVLOG.md` for dev logs and notes.
